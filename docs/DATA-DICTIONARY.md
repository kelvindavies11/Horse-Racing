# PostgreSQL data dictionary

Updated: 5 October 2026. This is the implemented domain and Raw schema after
`InitialCreate`, `ExpandRacingDomain`, and `AddRawIngestion`. See
[domain definitions and relationship diagram](DOMAIN-MODEL.md),
[migration instructions](DATABASE.md), [Raw collector guidance](BHA-RAW-COLLECTOR.md),
[source register](SOURCE-LINKS.md) and [generated PostgreSQL SQL](sql/DOMAIN-SCHEMA.sql).

## Conventions

All eleven domain tables have `id uuid NOT NULL` as their primary key, generated by the application, with no database UUID default. Foreign-key targets below are `id` unless otherwise stated. Required means `NOT NULL`; optional means nullable. Strings have the lengths shown; enum values are persisted as their names, not numeric C# ordinals. Internal IDs are not BHA/source IDs. Null describes missing or inapplicable data and is never a fabricated zero or empty identifier.

Domain tables use the connection's default PostgreSQL schema (`public` in the supplied
configuration). Raw source responses and source-to-Raw audit use the dedicated `raw`
schema. Created/Curated, promotion-audit, source-identity mapping and prediction tables are
not implemented. `__EFMigrationsHistory` is EF infrastructure, not a racing entity.

## Raw ingestion tables

### raw.collection_runs — source-to-Raw audit

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Application-generated collection-run identity / PK |
| job_name | varchar(100) | Yes | Stable local job name |
| source_name | varchar(200) | Yes | Human-readable source description |
| source_url | varchar(2048) | Yes | Requested BHA source location |
| collector_version | varchar(50) | Yes | Collector contract/code version |
| started_at_utc | timestamptz | Yes | Attempt start time |
| completed_at_utc | timestamptz | No | Completion time; null only while Running |
| outcome | varchar(20) | Yes | Running, Succeeded, Failed, or Cancelled |
| http_status_code | integer | No | Response status when a response was received |
| error_code | varchar(100) | No | Structured failure classification |
| error_message | varchar(2000) | No | Bounded diagnostic detail with no secrets |

Index `(source_url, started_at_utc)` supports source history and the minimum request
interval. CHECK constraints restrict outcomes and require completion timestamps for every
terminal result.

### raw.payloads — immutable found source data

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Application-generated Raw payload identity / PK |
| collection_run_id | uuid | Yes | Unique FK → raw.collection_runs |
| source_url | varchar(2048) | Yes | Requested BHA source location |
| effective_url | varchar(2048) | Yes | Final source location after allowed redirects |
| retrieved_at_utc | timestamptz | Yes | Time the response body was received |
| http_status_code | integer | Yes | Received HTTP result, including non-success results |
| media_type | varchar(200) | No | Response Content-Type media type |
| character_encoding | varchar(100) | No | Response-declared character set |
| entity_tag | varchar(500) | No | Response ETag when supplied |
| last_modified_utc | timestamptz | No | Response Last-Modified value when supplied |
| sha256 | char(64) | Yes | Lowercase SHA-256 of `content` |
| content_length | bigint | Yes | Stored byte count |
| content | bytea | Yes | Exact response bytes received by the collector |

Each collection run has at most one payload. HTTP error bodies are evidence and are stored;
network failures have an audit row but no invented payload. CHECK constraints validate the
HTTP status range, hash shape, and equality of `content_length` to the stored byte count.
The application has no Raw update or delete use case.

## Reference and connection tables

### racecourses — Racecourse

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Venue identity / PK |
| name | varchar(200) | Yes | Venue name; unique in the current scaffold |
| country_code | varchar(2) | Yes | Normalised country code, GB by default |

Unique index `ux_racecourses_name`. This existing name uniqueness is limited to the current British venue scope; international expansion must revisit it.

### horses — Horse

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Horse identity / PK |
| name | varchar(200) | Yes | Registered/display name |
| foaled_on | date | Yes | Exact foaling date; no future dates through the factory |
| country_code | varchar(2) | Yes | Source country code; precise source meaning must be mapped explicitly |

Non-unique search index `(name, foaled_on, country_code)`. These fields are not a safe provider identity key. Partial birth dates, pedigree and sex are future additions.

### stables — Stable

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Training yard identity / PK |
| name | varchar(200) | Yes | Yard name |
| town | varchar(200) | Yes | Yard locality |
| country_code | varchar(2) | Yes | Location country |

Non-unique search index `(name, town, country_code)`. Do not create a stable until the required location facts are known; a trainer or runner may have a null stable reference.

### trainers — Trainer

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Trainer/training-partnership identity / PK |
| stable_id | uuid | No | Current yard FK → stables |
| name | varchar(200) | Yes | Name as represented by the source |
| licence_number | varchar(100) | No | Licence reference when supplied |
| country_code | varchar(2) | Yes | Country qualifying the licence reference |

Unique `(country_code, licence_number)` when a licence is supplied; PostgreSQL allows multiple null licences. Stable FK indexed. Effective-dated licences and multiple yards are future work.

### jockeys — Jockey

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Rider identity / PK |
| name | varchar(200) | Yes | Rider display name |
| licence_number | varchar(100) | No | Licence reference when supplied |
| country_code | varchar(2) | Yes | Country qualifying the licence reference |

Unique `(country_code, licence_number)`; multiple null licences allowed. Names are not unique.

### owners — Owner

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Ownership identity / PK |
| display_name | varchar(200) | Yes | Individual/group racing name |
| type | varchar(20) | Yes | Individual, Partnership, Syndicate, Company, RacingClub |
| country_code | varchar(2) | Yes | Country associated with this ownership identity |

Non-unique `(display_name, type, country_code)` search index; type CHECK constraint. Ownership members and shares are not represented yet.

## Event and participation tables

### meetings — Meeting

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Fixture/session identity / PK |
| racecourse_id | uuid | Yes | FK → racecourses |
| name | varchar(200) | Yes | Meeting title |
| scheduled_date | date | Yes | Local course calendar date |
| type | varchar(20) | Yes | Flat, Jump, Mixed |
| status | varchar(20) | Yes | Scheduled, InProgress, Completed, Abandoned |

Non-unique `(racecourse_id, scheduled_date, name)` search index; type/status CHECK constraints. Two sessions may share course and date. A meeting can have zero races while its programme is being collected.

### races — Race

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Race identity / PK |
| meeting_id | uuid | Yes | FK → meetings; replaces the original direct racecourse_id |
| race_number | integer | Yes | Positive programme sequence within meeting |
| name | varchar(200) | Yes | Race title |
| scheduled_start_utc | timestamptz | Yes | Scheduled instant, normalised to UTC |
| code | varchar(30) | Yes | Flat, Hurdle, Steeplechase, NationalHuntFlat |
| surface | varchar(20) | Yes | Turf, AllWeather |
| distance_metres | integer | Yes | Positive distance in metres |
| going_description | varchar(100) | No | Going for this race, retaining descriptive wording |
| status | varchar(20) | Yes | Scheduled, Off, Finished, Abandoned |

Unique `(meeting_id, race_number)`; search index `(meeting_id, scheduled_start_utc)`. CHECK constraints enforce positive numbers and listed enum values. Racecourse is derived via Meeting. Race class/grade, eligibility and purse are still design gaps.

### runners — Runner

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Declaration identity / PK |
| race_id | uuid | Yes | FK → races |
| horse_id | uuid | Yes | FK → horses |
| trainer_id | uuid | Yes | Trainer for this declaration; FK → trainers |
| owner_id | uuid | Yes | Racing ownership identity for this declaration; FK → owners |
| jockey_id | uuid | No | Booked rider; FK → jockeys |
| stable_id | uuid | No | Yard at this race; FK → stables, independent of trainer's current yard |
| cloth_number | integer | Yes | Positive saddlecloth number |
| draw | integer | No | Positive stall draw, distinct from cloth |
| carried_weight_pounds | integer | No | Positive weight in pounds |
| declared_odds | numeric(10,4) | No | Decimal total-return quote, greater than 1; not a time series |
| status | varchar(20) | Yes | Declared or NonRunner |
| non_runner_reason | varchar(500) | No | Required nonblank text for NonRunner; null for Declared |

Unique `(race_id, horse_id)`, `(race_id, cloth_number)`, and partial unique `(race_id, draw) WHERE draw IS NOT NULL`. Alternate key `(id, race_id)` supports same-race result integrity. Connection FKs are indexed. CHECK constraints enforce positive numbers, valid decimal odds and status/reason consistency.

## Result tables

### race_results — RaceResult

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Current result identity / PK |
| race_id | uuid | Yes | Unique FK → races |
| published_at_utc | timestamptz | Yes | Current publication timestamp |
| status | varchar(20) | Yes | Provisional or Official |
| winning_time | interval | No | Positive winning duration, not time of day |

Unique `race_id` enforces zero/one result per race. Alternate key `(id, race_id)` supports composite result references. CHECK constraints validate duration and status. Revision history is not implemented; official results are immutable through domain methods.

### runner_results — RunnerResult

| Column | PostgreSQL type | Required | Meaning |
| --- | --- | --- | --- |
| id | uuid | Yes | Starter outcome identity / PK |
| race_result_id | uuid | Yes | Parent result, part of composite FK |
| race_id | uuid | Yes | Shared race identity for both composite FKs |
| runner_id | uuid | Yes | Unique runner, part of composite FK |
| outcome | varchar(30) | Yes | Finished, PulledUp, Fell, UnseatedRider, Refused, BroughtDown, RanOut, Disqualified, Void |
| finish_position | integer | No | Positive position for Finished; must be null otherwise |
| is_dead_heat | boolean | Yes | Tie marker; false for non-finishers |
| distance_beaten_lengths | numeric(8,3) | No | Nonnegative cumulative lengths behind winner (ingestion must normalise margins) |
| starting_price_decimal | numeric(10,4) | No | Decimal total-return SP greater than 1 |
| prize_money | numeric(14,2) | No | Nonnegative GBP prize amount for this runner |

Composite FKs `(race_result_id, race_id) → race_results(id, race_id)` and `(runner_id, race_id) → runners(id, race_id)` prevent attaching an outcome to a different race. Unique `runner_id`; non-unique `(race_result_id, finish_position)` permits dead heats. EF also generates supporting composite-FK indexes. CHECK constraints validate outcomes, positions and numeric values. Cross-row dead-heat, non-runner, official-completeness and publication rules remain domain rules, not SQL CHECK constraints.

## Relationship and deletion matrix

| Child FK | Parent | Cardinality from parent | ON DELETE |
| --- | --- | --- | --- |
| meetings.racecourse_id | racecourses.id | 1 → many meetings | RESTRICT |
| races.meeting_id | meetings.id | 1 → many races | RESTRICT |
| trainers.stable_id | stables.id | 0/1 yard per trainer; many trainers per yard | RESTRICT |
| runners.race_id | races.id | 1 → many declarations | CASCADE |
| runners.horse_id | horses.id | 1 → many declarations | RESTRICT |
| runners.trainer_id | trainers.id | 1 → many declarations | RESTRICT |
| runners.owner_id | owners.id | 1 → many declarations | RESTRICT |
| runners.jockey_id | jockeys.id | 0/1 jockey per runner; many rides per jockey | RESTRICT |
| runners.stable_id | stables.id | 0/1 yard per runner; many runners per yard | RESTRICT |
| race_results.race_id | races.id | 1 → zero/one current result | CASCADE |
| runner_results.(race_result_id, race_id) | race_results.(id, race_id) | 1 → many outcomes | CASCADE |
| runner_results.(runner_id, race_id) | runners.(id, race_id) | 1 → zero/one outcome | RESTRICT |

Reference records cannot be deleted while referenced. There is no general delete use case: runners with results are protected, so a future aggregate deletion workflow must explicitly remove result dependants before runners. Prefer retaining historical racing records. Rollback of this schema removes expanded data; see the migration guidance.

## Synchronisation rule

For a domain change, update entity code, EF configuration, migration/snapshot, this dictionary and the domain dictionary together. Regenerate `docs/sql/DOMAIN-SCHEMA.sql` from EF migrations, then run the [SQL relationship checks](../tests/sql/verify-domain.sql). Do not hand-edit the generated SQL independently of its migrations.
